## What was built
1. **`src/lib/fluxdrop/secure-store.ts` (new)**
   - Own IndexedDB: `fluxdrop-keys` / `keys` store (idb-keyval `createStore`; new DB so the "store only created on new DB" caveat doesn't apply).
   - `getAtRestKey()`: generates a **non-extractable** AES-256-GCM CryptoKey once (`extractable=false`, usages `encrypt/decrypt`), persists the **CryptoKey object itself** (structured-cloneable, stays non-extractable after clone), caches in module scope, dedupes concurrent generations, shape-guards the persisted key on reuse.
   - `encryptAtRest` / `decryptAtRest`: `nonce(12B) || AES-256-GCM ciphertext`, AAD `'fluxdrop:at-rest:v1'`.
   - Envelope: `{ __fluxdropEnc: 1, data: ArrayBuffer }` + `isEncryptedEnvelope()` + `sealValue()`/`unsealBytes()`.
   - `atRestEncryptionAvailable()`: false on SSR, insecure contexts (no `crypto.subtle`), no IndexedDB, or after key-pipeline failure → callers fall back to plaintext (never break transfers).
   - `initParanoidMode()` self-invoked at module scope (idempotent, `typeof window` guard): reads `fluxdrop:paranoid-mode` from localStorage directly, purges leftover chunk keys at load (crash recovery), registers `pagehide` + best-effort `beforeunload` listeners that purge all `chunk:` keys.
2. **`src/lib/fluxdrop/resume.ts` (modified)**
   - `saveChunk`/`getChunk` route through the envelope; legacy plaintext chunks serve as-is + background re-seal (transparent migration, deduped). Undecryptable chunks read as *absent* → sender re-transfers.
   - History records: `saveTransferRecord`, `updateTransferRecord` final set, and `flushAcked` all funnel through private `writeTransferRecord()` (JSON bytes → envelope). Updaters still receive the DECRYPTED record. Write-queue semantics unchanged.
   - `getTransferRecord`/`listTransfers` decrypt envelopes; legacy plaintext objects pass a light shape guard.
   - New export `wipeChunkCache(): Promise<number>`; `saveSenderFiles` left plaintext per task.
   - Statically imports `./secure-store` (arming happens via secure-store's module-scope self-init; no use-fluxdrop.ts change).
3. **`src/stores/session-store.ts`**: `paranoidMode` (default false) + `setParanoidMode` persisted to `fluxdrop:paranoid-mode`, loaded in `initDevice` (useTurnRelay pattern).
4. **`src/components/fluxdrop/flux-header.tsx`**: Settings → Privacy tab, new "Paranoid mode" block between the E2E (PIN-sealed) block and Trusted devices; Switch wired to store; ON → immediate `wipeChunkCache()` + sonner toast (exact requested message; count-prefixed when >0).

## Key decisions
- Circular-import avoidance: secure-store → resume is a **dynamic** import inside the purge function; resume → secure-store is the only static edge. The dynamic import resolves only after resume finishes evaluating, which also makes the load-time leftover purge safe.
- Key persistence happens **before** any value can be sealed with the key (no orphan-ciphertext window if IDB set fails).
- TS 5.9 `BufferSource` fix: Uint8Array inputs are wrapped once into ArrayBuffer-backed views (chunk saves pass ArrayBuffer → zero-copy).

## Caveats / risks for the main agent
- Paranoid pagehide fires on **reload** too: with the flag on, mid-transfer reload discards partial chunks by design (settings copy documents this; history metadata survives; transfer restarts).
- If `fluxdrop-keys` DB were wiped while the other DBs survive (profile surgery), sealed values read as absent → graceful degradation (re-transfer / missing history rows). Sandbox reloads wipe all IDB together.
- Insecure-context deployments (plain http over LAN IP) silently fall back to plaintext — same constraint as the SPAKE2 E2E feature.
- Upcoming E2E browser regression should exercise: receiver chunk persistence (envelope), history rows (decrypted), paranoid toggle toast, legacy plaintext records still listed.
